## `clickhouse/02_intervention_decay_asof.sql` — intervention decay asof

**Вопрос:** как затухает эффект каждого вида ГТМ — во сколько раз дебит выше, чем до мероприятия, через 1, 3, 6 и 12 месяцев после его окончания? Особенности ClickHouse: * ASOF JOIN — к каждому дню добычи присоединяется ПОСЛЕДНЕЕ завершённое ГТМ на этой скважине (в PostgreSQL понадобился бы LATERAL с ORDER BY ... LIMIT 1); * комбинатор -If (medianExactIf) — «разворот» месяцев в столбцы за один проход. Медиана точная (Exact): обычная median в ClickHouse приближённая (по выборке) и может слегка меняться от запуска к запуску — для отчётов это недопустимо. Медиана, а не среднее: при низком дебите «до» (ЗБС на почти выбывших скважинах) отношение очень велико, и среднее перекосили бы единичные выбросы.

## `clickhouse/03_start_rate_quantiles.sql` — start rate quantiles

**Вопрос:** как распределены стартовые дебиты новых скважин (первые 90 суток) по типу ствола и какая скважина лучшая в каждом типе? Особенности ClickHouse: * quantilesExact(...) — несколько точных квантилей за один проход по данным; * argMax(x, y) — значение x в строке с максимальным y, без подзапроса; * arrayMap с лямбдой — округление элементов массива.
